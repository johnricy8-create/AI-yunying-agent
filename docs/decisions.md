## 2. 架构决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 阶段一状态直接携带 DataFrame；阶段五再迁移为引用式 | 无检查点需求，保持简单 |
| D2 | 保留 `ai_recommend` 占位节点 | 阶段二只替换实现，不改图结构与报告模板 |
| D3 | 业务配置用 YAML，密钥用 `.env` | 可读、可注释、业务与密钥分离 |
| D4 | 报告按 `YYYY-MM-DD_daily_report.md` 命名，同日覆盖 | 保持每日一份主报告；run_id 留在报告与日志 |
| D5 | 内部字段英文，报告中文 | 避免中文表头在编码、Excel、后续模型输入中反复出问题 |
| D6 | 阶段一报告包含规则型核查方向，醒目标注非 AI | 不让报告空着，也不伪造模型结论 |
| D7 | 扁平包 `ecom_ops/`，不引入 `src/` 布局 | 激活虚拟环境后 `python run.py` 直接可跑，无需安装本项目 |

## 3. 技术栈决策

| 编号 | 决策 | 理由 |
|---|---|---|
| T1 | Python 3.12.15 | 已由 uv 安装，生态成熟，避开 3.15 的依赖风险 |
| T2 | uv + 项目内 `.venv` + 单一冻结 `requirements.txt` | 无需系统 Python；符合文档要求；版本可复现 |
| T3 | YAML + python-dotenv | 业务阈值与密钥分离；配置可读可注释 |
| T4 | Jinja2 报告模板 | 报告结构与代码分离，表格/循环可维护 |
| T5 | pytest | 指标、基线、规则边界适合参数化测试 |
| T6 | 标准库 logging | 零额外依赖，按天轮转足够 |
| T7 | zoneinfo + tzdata | Windows 不自带 IANA 时区库，必须显式安装 tzdata |
| T8 | 阶段一不装完整 LangChain、openpyxl、APScheduler | 分别留到阶段二、三、四，避免未使用依赖 |
| T9 | BGE-M3 暂缓 | 它是嵌入模型，不是对话模型；阶段一/二核心流程不需要，阶段五再评估 RAG |

## 4. 阈值默认值（v0.1）

| 参数 | 默认值 |
|---|---|
| 基线窗口 | 3 / 5 / 7 天 |

| 新品豁免 | 1 天 |

| 浏览量骤降 | ≤ 基线 × 0.7，且基线 PV ≥ 50 |
| 订单骤降 | ≤ 基线 × 0.7，且基线订单 ≥ 3 |
| 高浏览低转化 | PV ≥ 基线 × 1.2，CR ≤ 基线 CR × 0.6，且 PV ≥ 100 |
| 严重度基础分 | 零转化 50 / PV 骤降 30 / 订单骤降 30 / 高浏览低转化 25 |
| 严重度分级 | ≥70 高危，≥40 中危，其余低危 |
| Top-N | 10 |

**状态**：这些是阶段一默认值，尚未用真实业务数据校准。阶段三接入真实数据后应复盘调整，调整需记录在本文件。

## 5. 数据质量策略

| 决策 | 说明 |
|---|---|
| 坏行隔离而非整批失败 | 单行问题不影响其他商品 |
| 重复键保留最后一条 | 被覆盖行标记 `duplicate_key` |
| 可选字段缺失给默认值并警告 | 简介空、店铺/平台/类目“未填写” |
| 未来日期视为错误 | 模拟数据使用固定 2099-01-01 样本，保证长期可复现 |
| 无有效行时失败退出 | 不生成误导性报告 |
