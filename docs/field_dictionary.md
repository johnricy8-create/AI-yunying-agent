# 字段字典与数据质量规则

## 1. 字段契约

内部统一使用英文 `snake_case`；报告展示使用中文标签。阶段一模拟数据直接使用内部字段名，阶段三接入真实 CSV/Excel 时通过 `config/fields.yaml` 的 `aliases` 做表头映射。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| stat_date | 统计日期 | date | 是 | `YYYY-MM-DD`；一行代表一个商品一天 |
| product_id | 商品ID | string | 是 | 商品唯一标识 |
| product_name | 商品名称 | string | 是 | 展示名称 |
| product_desc | 商品简介 | string | 否 | 为空时报告显示为空，并产生警告 |
| shop | 店铺 | string | 否 | 为空时填“未填写” |
| platform | 平台 | string | 否 | 为空时填“未填写” |
| category | 类目 | string | 否 | 为空时填“未填写” |
| price | 单价 | float | 是 | 必须大于 0 |
| cost | 成本 | float | 否 | 默认 0；阶段一不参与核心指标，仅做成本高于单价的警告 |
| stock | 库存 | int | 是 | 必须 >= 0；阶段一仅展示与校验 |
| pv | 浏览量 | int | 是 | 当前业务口径等同 UV，作为转化率分母 |
| uv | 访客数 | int | 否 | 可选；存在且 > 0 时优先作为转化率分母，否则回退 pv |
| orders | 订单量 | int | 是 | 必须 >= 0，且不能大于 pv / uv |
| sales_amount | 销售额 | float | 是 | 已扣除退款、不含税的净额；程序不再二次扣减 |
| refund_amount | 退款金额 | float | 否 | 默认 0；仅用于退款率与校验 |

### 业务口径

- 转化率 = `orders ÷ (uv if uv > 0 else pv)`。
- 浏览量变化率 = `(今日 pv − 昨日 pv) ÷ 昨日 pv`；昨日为 0 或缺失时不记录，报告显示“—”。
- 销售额是净额；退款金额不再从销售额中扣减。
- 主键为 `product_id + stat_date`；重复时保留最后一条，之前的标记为错误。
- 缺失日期不插值；基线只使用有效历史数据。

### 中文表头别名（部分）

`日期/统计日期`、`商品ID/商品编号/SKU`、`商品名称/商品名`、`商品简介/简介/描述`、`店铺/店铺名称`、`平台`、`类目/分类`、`单价/价格`、`成本`、`库存`、`浏览量/PV`、`访客数/UV`、`订单量/订单数`、`销售额/销售金额`、`退款金额/退款`。

完整映射见 `config/fields.yaml`。

## 2. 校验与数据质量

### 错误（行被隔离，不参与指标）

| 代码 | 含义 |
|---|---|
| missing_required | 必填字段为空 |
| invalid_date | 日期格式错误 |
| invalid_number | 数字字段无法解析 |
| negative_value | 数值为负 |
| non_positive_price | 单价 <= 0 |
| orders_gt_pv | 订单量大于浏览量 |
| orders_gt_uv | 订单量大于访客数（uv 存在且 > 0 时） |
| refund_gt_sales | 退款金额大于销售额 |
| future_date | 统计日期晚于今天 |
| duplicate_key | 商品 + 日期重复；保留最后一条 |

### 警告（行保留，报告中提示）

| 代码 | 含义 |
|---|---|
| missing_optional | 可选字段为空，已填默认值（简介为空、店铺/平台/类目为“未填写”） |
| cost_gt_price | 成本高于单价 |
| zero_sales_with_orders | 有订单但销售额为 0，需核对是否为赠品或数据缺失 |

### 隔离策略

- 坏行不会导致整批任务崩溃；校验后如果没有可用行，任务失败退出。
- 被隔离的行会在报告“数据概览”中按错误类型统计，并展示最多 10 行样例（行号、商品ID、日期、原因）。
- 未知列不会参与分析，但会在日志中告警，便于阶段三排查真实数据。

## 4. 阶段三扩展

- 支持 `.xlsx` 时引入 `openpyxl`，并在 `loader.py` 增加读取分支。
- 真实表头可能不统一，优先在 `config/fields.yaml` 增加别名，而不是改代码。
- 编码优先 UTF-8 with BOM；读取时依次尝试 UTF-8-SIG、UTF-8、GBK。
- 不假设已有真实电商平台 API；阶段三只处理本地 CSV/Excel。
- 真实数据可能包含个人信息，建议只导出商品级聚合数据，不要把订单明细或客户信息写入报告与日志。
