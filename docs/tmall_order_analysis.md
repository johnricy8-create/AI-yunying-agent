# 天猫订单经营分析（真实数据分支）

## 1. 数据来源

样本位置：

```text
D:\天猫销售数据\Tmall_Tableau_Visualization_Project\data\tmall_order_report.csv
```

这是天猫 2020 年 2 月的订单级交易数据，共 28,010 行、7 个字段。源项目是 SQL + Tableau 分析；本仓库直接读取原始 CSV，重新做清洗、核算和 Markdown 报告。

| 原始字段 | 内部字段 | 说明 |
|---|---|---|
| 订单编号 | `order_id` | 订单唯一标识 |
| 总金额 | `total_amount` | 订单原金额 |
| 买家实际支付金额 | `paid_amount` | 退款后的实际支付净额；未支付为 0 |
| 收货地址 | `province` | 省级收货地址 |
| 订单创建时间 | `created_at` | 下单时间 |
| 订单付款时间 | `paid_at` | 付款时间；未支付为空 |
| 退款金额 | `refund_amount` | 支付后的退款金额；无退款为 0 |

源文件实际编码是 **GBK**，不是源 README 写的 UTF-8；`收货地址 `、`订单付款时间 ` 两个表头带尾部空格。加载器会尝试 GBK → UTF-8-SIG → UTF-8，并统一去除表头空格。

## 2. 为什么单独一条分支

天猫数据是订单级，缺少当前商品级日报需要的：

- SKU / 商品 ID / 商品名称；
- PV / UV；
- 库存；
- 成本；
- 商品维度退款。

因此不能把它硬塞进 `product_id + pv + uv + orders` 的商品级 Agent，否则会产生虚假的商品、流量和转化率。天猫分支只做：

```text
订单 CSV → 清洗/隔离 → 订单级 KPI → 漏斗 → 每日/省份/时段 → Markdown 报告
```

该分支不调用大模型，不写入商品级历史库，不参与 v0.1 阈值校准。

## 3. 口径

| 指标 | 定义 |
|---|---|
| 下单数 | 所有有效订单 |
| 支付数 | 有付款时间 |
| 成交数 | 实际支付金额 > 0 |
| 全价成交数 | 成交且总金额 = 实际支付金额 |
| 零实付/全额退款 | 已支付但实际支付金额 = 0 |
| 支付率 | 支付数 ÷ 下单数 |
| 成交率 | 成交数 ÷ 下单数 |
| 退款订单数 | 退款金额 > 0 的订单 |
| 退款订单率 | 退款订单数 ÷ 支付订单数 |
| 退款金额占比 | 退款金额 ÷ 支付订单原金额 |
| 客单价 | 实际支付净额 ÷ 成交数 |

**关键字段关系**：对全部 24,087 个支付订单，源数据满足：

```text
总金额 = 实际支付金额 + 退款金额
```

因此 `实际支付金额` 已经是退款后的净额。报告展示“实际支付净额”，不再用 `实际支付 − 退款` 二次扣减，否则会低估收入。

## 4. 当前真实数据结果（2020-02）

| 指标 | 数值 |
|---|---:|
| 下单 | 28,010 |
| 支付 | 24,087 |
| 成交（实付 > 0） | 18,955 |
| 全价成交 | 18,441 |
| 零实付/全额退款 | 5,132 |
| 支付率 | 85.99% |
| 成交率（下单口径） | 67.67% |
| 退款订单 | 5,646 |
| 支付订单原金额 | 2,474,823.07 |
| 退款金额 | 572,335.92 |
| 实际支付净额 | 1,902,487.15 |
| 退款金额占原金额 | 23.13% |

日期质量：

- 按订单创建日：2020-02-08、2020-02-16 没有订单；
- 按付款日：2020-02-16 没有支付记录；
- 2020-02-10 至 2020-02-15 订单量明显偏低；
- 少量 2 月 29 日订单在 2020-03-01 付款，因此付款日序列会多出 2020-03-01。

这些日期可能代表缺失数据，也可能代表真实零单；报告只标注，不自动判定为异常。

## 5. 与源 Tableau/SQL 项目的关系

源项目使用同样的原始数据，但它的 Tableau/SQL 结果与直接读 CSV 可能因清洗版本、口径实现不同而有差异。本仓库：

- 以当前 CSV 为准重新计算；
- 在报告中明确写出每个口径；
- 不复制源项目的 KPI 数字；
- 不把源项目的“成交”与“全额退款”混为一个概念。

源项目漏斗中“成交”定义为 `实际支付金额 > 0`，本分支一致；源项目还展示“全额成交”，本分支按 `总金额 = 实际支付金额` 重新核算。当前 CSV 直接计算的全价成交为 **18,441 单**，源项目 Tableau 展示 **16,650 单**，差异 1,791 单；可能来自源项目 SQL 清洗版本或数据版本差异，本分支未强行对齐。若与源项目 Tableau 数字不一致，应先核对数据版本和清洗 SQL，而不是直接修改本分支结果。

## 6. 运行

```powershell
  --data "D:\path\tmall_order_report.csv" `
  --output reports\tmall\custom.md
```

输出：

```text
reports/tmall/2020-02_tmall_order_report.md
```

`reports/tmall/` 已加入 `.gitignore`，真实订单报告不进入 Git。

## 7. 限制

- 单月数据，不能外推到全年或大促周期；
- 无 SKU/商品维度，不能定位具体商品；
- 无 PV/UV，不能计算商品转化率；
- 无库存/成本，不能做库存和毛利分析；
- 退款原因、订单状态、渠道、平台费用均缺失；
- 退款金额与支付净额的口径来自源字段关系，未做财务对账；
- 不调用大模型，建议需人工结合业务判断。
